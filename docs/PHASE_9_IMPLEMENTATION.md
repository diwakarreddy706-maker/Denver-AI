# Phase 9 — Denver Intelligent Task & Workflow Orchestration Implementation

## Overview
Phase 9 extends the Denver AI Assistant with structured, bounded, and deterministic multi-step task planning and DAG workflow execution without introducing unbounded autonomous-agent loops.

## Core Architectural Principles
1. **Untrusted AI Proposals**: Task plans generated by AI or LLMs are treated strictly as untrusted declarative proposals.
2. **Re-Validation Gate**: Every individual workflow step must pass safety revalidation immediately before execution:
   `SafetyValidator` $\rightarrow$ `ActionRegistry` $\rightarrow$ `AutomationExecutor`
3. **Immutable Plans**: Once execution starts, `TaskPlan` instances are immutable.
4. **Bounded Execution**: Configurable concurrency ($\le 2$), execution timeouts, step timeouts ($\le 60\text{s}$), DAG depth limits ($\le 10$), and max steps ($\le 20$).
5. **Deterministic Storage**: SQLite Migration v4 on `denver_memory.sqlite3`.

## Architecture Diagram
```
User / Router / Routine
        │ (Proposal)
        ▼
   TaskPlanner (Plan Parsing & Construction)
        │
        ▼
   PlanValidator (DAG Cycle Check, Depth <= 10, Action Existence)
        │
        ▼
   TaskRegistry ──► TaskPersistence (SQLite v4)
        │
        ▼
   WorkflowEngine (DAG Scheduler & Worker Pool)
        │
        ├─► SafetyValidator (Step Parameter Re-Validation)
        ├─► TaskApprovalManager (Explicit Confirmation Tokens)
        ├─► ActionRegistry ──► AutomationExecutor
        ├─► TaskAuditLogger (Structured Telemetry)
        └─► EventBus (Typed Lifecycle Events)
```

## Database Schema (Migration v4)
- `orchestrated_tasks`: Top-level task entities (`task_id`, `title`, `origin`, `priority`, `status`, `current_plan_id`).
- `task_plans`: Versioned DAG plans (`plan_id`, `task_id`, `status`, `failure_policy`, `max_retries`, `timeout_seconds`, `concurrency_limit`).
- `task_steps`: Discrete steps with dependency lists (`step_id`, `plan_id`, `action_name`, `params`, `depends_on`, `requires_approval`).
- `task_executions`: Full workflow execution runs (`execution_id`, `task_id`, `plan_id`, `status`, `started_at`, `completed_at`, `error_summary`, `result_data`).
- `step_executions`: Individual step attempt records (`step_execution_id`, `execution_id`, `step_id`, `status`, `duration_ms`).
- `task_audit`: Immutable audit trail (`audit_id`, `task_id`, `event_type`, `actor`, `details`, `created_at`).
